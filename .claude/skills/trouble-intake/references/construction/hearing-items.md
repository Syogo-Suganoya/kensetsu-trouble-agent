# ヒアリング項目

## 必須（ログ登録に必要）

| 項目 | JSON | 聞き方の例（選択肢付き） |
|---|---|---|
| 何が起きたか | `summary.what` | 報告文から作る。曖昧なら「①まだ来てない ②来たけど足りない ③違う物が来た」 |
| いつ | `summary.when` | 「発生は ①今さっき ②今朝 ③昨日以前 ④これから（予定）」 |
| どこで | `summary.where` | 「場所は何階／どの工区？（わからなければ『不明』でOK）」 |
| 影響範囲 | `summary.impact` | 「今日の作業は ①止まる ②一部止まる ③止まらない」＋待機人数・次工程への影響 |
| 関係者 | `summary.stakeholders` | 「関係する会社・人は？ 例：元請の担当者、メーカー、前工程の業者」 |
| 報告者 | `reporter` | 「あなたは ①職人 ②協力会社（職長・事務） ③元請」「何次の下請ですか？（わからなければ飛ばしてOK）」 |
| 現場名 | `site` | 「現場名は？（通称でOK）」 |

## あると後で効く（聞けたら `impact` や `what` に含める）

- **誰の指示・誰の起因か（事実として）**：「〇〇さんから口頭で指示」「前工程の△△が未完了」— 後の交渉材料になる
- **待機・手待ちの人数と時間**：手待ち時間はサビ残・追加費用の根拠になる
- **写真の有無**：「写真撮ってありますか？」（撮っていなければ撮影を勧める）
- **既に誰に連絡したか**：二重連絡・連絡漏れを防ぐ

## 聞き方のルール

- 1回1〜2問、番号で答えられる形にする。
- 報告文から推測できるものは質問にせず、確認サマリで「合ってますか？」とまとめて確認する。
- 3往復で埋まらなければ `不明` のまま登録し、後から `trouble-log` で追記できると伝える。
