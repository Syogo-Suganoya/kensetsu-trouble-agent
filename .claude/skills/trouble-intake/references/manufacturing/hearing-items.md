# ヒアリング項目（中小製造業サプライヤー）

## 必須（ログ登録に必要）

| 項目 | JSON | 聞き方の例（選択肢付き） |
|---|---|---|
| 何が起きたか | `summary.what` | 報告文から作る。品番・工程がわかれば含める |
| いつ | `summary.when` | 「連絡を受けた／発生したのは ①今さっき ②今朝 ③昨日以前」＋**納期・要求納期** |
| どこで | `summary.where` | 「工場・ライン・工程は？（例：第2工場 プレス3号機）」 |
| 影響範囲 | `summary.impact` | 「納入に ①間に合わない ②ギリギリ ③影響なし」＋数量・残業や休日出勤の要否 |
| 関係者 | `summary.stakeholders` | 「発注元の担当部署（購買／品証／生産管理）、仕入先・外注先は？」 |
| 報告者 | `reporter` | 「あなたは ①作業者 ②サプライヤー（管理・営業・事務） ③発注元」「発注元から見て何次の取引先ですか？（Tier1=1、わからなければ飛ばしてOK）」 |
| 現場名 | `site` | 「工場名・取引先名／品番は？（通称でOK）」 |

`reporter.role` は `作業者` / `サプライヤー` / `発注元`。

## あると後で効く（聞けたら `impact` や `what` に含める）

- **依頼・指示の経路と日時**：「購買の〇〇さんから電話で」「内示は先月〇日、確定は昨日」— 口頭・電話のみなら書面化を勧める
- **数量の変化**：内示数→確定数、当初納期→要求納期
- **発生する追加コスト**：残業・休日出勤の人数×時間、特急の材料手配費、選別・手直しの工数、余剰在庫
- **価格の話が出ている場合**：前回の価格協議の時期、原材料・エネルギー・労務費の上昇について申し入れたか
- **不良の場合**：ロット・数量・発見場所（自社／発注元受入／発注元ライン）、現品・写真の有無

## 聞き方のルール

- 1回1〜2問、番号で答えられる形にする。
- 報告文から推測できるものは質問にせず、確認サマリで「合ってますか？」とまとめて確認する。
- 3往復で埋まらなければ `不明` のまま登録し、後から `trouble-log` で追記できると伝える。
