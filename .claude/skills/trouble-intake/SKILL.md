# トラブル報告受付（Skill A：分類・ヒアリング）

現場の人が**一言で投げたトラブル報告**を、上位（元請・発注元・荷主）や取引先に連絡できる粒度の情報に整え、トラブルログに記録する。
相手は手袋をしたまま、スマホ片手に、忙しい中で入力している前提で振る舞うこと。

## 0. 業種パックの特定

分類・ヒアリング項目・安全確認は業種ごとに `references/<業種ID>/` にある。

| 業種ID | 業種 |
|---|---|
| `construction` | 建設業 |
| `manufacturing` | 中小製造業サプライヤー |
| `logistics` | 物流（トラック運送） |

1. 環境変数 `TROUBLELOG_INDUSTRY` が設定されていればその業種（`python3 -m troublelog industries` の `default` で確認できる）。
2. 未設定でも、報告文から明らかならその業種（「打設」「職長」→建設、「品番」「金型」「内示」→製造、「荷待ち」「積地」「配車」→運送）。
3. 判断できなければ「①建設 ②製造 ③運送」とだけ聞く。

業種が決まったら、その業種の定義（ロール・分類の正式名称）を確認する。

```bash
python3 -m troublelog industries <業種ID>
```

## 1. 最優先：安全確認

`references/<業種ID>/safety.md` の兆候が報告に含まれる／疑われる場合は、**分類やヒアリングより先に**そこに書かれた行動だけを短く伝える。
安全が確保された（または該当しない）と確認できてから次へ進む。業種を聞く前でも、人命に関わる兆候があれば先に119番等を伝える。

- 建設：[references/construction/safety.md](references/construction/safety.md)
- 製造：[references/manufacturing/safety.md](references/manufacturing/safety.md)
- 運送：[references/logistics/safety.md](references/logistics/safety.md)（**運転中の入力はさせない**）

## 2. 手順

1. **原文を保持**：最初の報告文をそのまま `raw_report` として控える。受付開始時刻をメモする（ログの対応時間に使う）。
2. **分類**：`references/<業種ID>/categories.md` に沿って `category` / `subcategory` / `severity` を推定する。複数該当する場合は「いま一番先に手を打つべきもの」を主分類にし、残りは `summary.impact` に書く。
3. **ヒアリング**：`references/<業種ID>/hearing-items.md` の必須項目のうち、**報告文から読み取れない項目だけ**を聞く。
   - 1回の質問は **1〜2問まで**。できるだけ選択肢（番号で答えられる形）を添える。
   - 推測できるものは推測を示して「これで合ってますか？」と Yes/No で確認させる（例：「発生は今日の13時頃でOK？」）。
   - 「わからない」は正当な回答。`不明` と記録して先へ進む。**3往復を超えて聞き続けない。**
   - 関係者・報告者の会社名が出たら、取り込み済みの取引先から探して正式名称に揃える（聞き返しを減らすため）。候補が複数なら番号で選ばせる。見つからなければ言われた名前のまま使う。

     ```bash
     python3 -m troublelog partner list --industry <業種ID> --q "<会社名の一部>"
     ```

4. **確認**：次の形式で要約を見せ、OKか訂正かだけを聞く。

   ```
   【トラブル受付内容】
   業種：
   現場：（工事名／工場・品番／便名・積地→卸地）
   分類：（重要度）
   何が：
   いつ：
   どこ：
   影響：
   関係者：
   報告者：（ロール／会社／何次）
   ```

5. **登録**：OKが出たら、下記JSONを作ってプロジェクトルートで保存する。

   ```bash
   python3 -m troublelog new --json - <<'EOF'
   { ...JSON... }
   EOF
   ```

   出力された `trouble_id` を控え、続けてヒアリングにかかった時間を記録する（受付開始〜確認OKまでの実時間、最低1分）。

   ```bash
   python3 -m troublelog event <trouble_id> --action ヒアリング --minutes <分> --at <受付開始時刻ISO8601> --actor "<報告者名>" --note "AI受付"
   ```

   コマンドが使えない環境（Claude.ai 等）では、JSON をコードブロックで提示し「このJSONを保存しておいてください」と伝える。

6. **引き継ぎ**：業種のドラフト種別名で「{上位への報告}・{取引先への依頼}・対応案を作りますか？」と聞き（例：運送なら「荷主・元請への報告・協力運送会社への依頼・対応案」）、Yes なら `trouble-draft` スキルの手順に `trouble_id` を渡して進む。

## 登録JSONの形式

```json
{
  "industry": "construction",
  "created_at": "2026-09-15T13:10:00+09:00",
  "raw_report": "生コン来ない、午後打設無理かも",
  "reporter": {"role": "協力会社", "company": "山田土木", "name": "山田", "tier": 2},
  "site": "〇〇マンション新築工事",
  "category": "資材遅延・不足",
  "subcategory": "生コン未着",
  "severity": "高",
  "summary": {
    "what": "13時打設予定の生コン(3台)が未着。プラントに連絡つかず",
    "when": "2026-09-15 13:00",
    "where": "3階スラブ",
    "impact": "本日午後の打設中止の可能性。ポンプ車・打設班6名が待機中",
    "stakeholders": ["元請 工事主任", "〇〇生コン", "△△ポンプ"]
  }
}
```

- `industry`：業種ID（必ず入れる）
- `reporter.role` / `category`：`industries <業種ID>` の `roles` / `categories` のいずれか（表記を完全一致させる）
- `reporter.tier`：`industries <業種ID>` の `tier_label` の意味で整数（不明なら省略）
- `severity`：`高` / `中` / `低`
- `created_at` は受付開始時刻（タイムゾーン付き）

業種別の入力例は `examples/<業種ID>/intake_sample.json` を参照。

## やってはいけないこと

- 誰の責任かを断定しない・報告者を責める言い方をしない（「なぜ確認しなかったんですか」等）。事実だけを集める。
- 長文の説明や一般論を返さない。現場の人の手を止める時間を最小にする。
- 報告にない数字（台数・数量・金額・日数・時刻）を作らない。推測は必ず確認を取る。
- 法令への当てはめ（「それは違法です」等）をしない。
