# 対応ログ記録・集計（Skill C）

「見えない労働」を見えるようにするスキル。入力の手間をかけさせず、会話の一言から対応時間を記録する。

## A. 対応を記録する

1. **対象の特定**：`trouble_id` が不明なら一覧から候補を出して番号で選ばせる（1件しかなければ確認だけ）。

   ```bash
   python3 -m troublelog list --status 対応中
   python3 -m troublelog list --status 受付
   ```

2. **自然文 → イベント変換**：

   | 項目 | 読み取り方 | 不明なとき |
   |---|---|---|
   | `--action` | 電話・LINE・メール→`連絡`／打合せ・日程や段取りの調整→`調整`／報告書・写真整理・是正報告→`書類作成`／現場に行った・立会い・是正作業→`現場対応`／それ以外→`その他`。**業種固有**：製造 選別・手直し→`選別・手直し`／運送 荷待ち・順番待ち→`荷待ち`、棚入れ・仕分け・手積み等→`附帯作業`（一覧は `python3 -m troublelog industries <業種ID>` の `actions`） | 推測して確認 |
   | `--minutes` | 「20分」「1時間半」→90。「〜から〜まで」は差分 | **必ず聞く**（「だいたい何分くらい？ ①15分 ②30分 ③1時間 ④それ以上」） |
   | `--at` | 「昨夜23時」「さっき」「今朝7時」を ISO8601（+09:00）に変換。「さっき」は 現在時刻−所要時間 | 現在時刻−所要時間 |
   | `--actor` | 本人なら報告者名 | ログの `reporter.name` |
   | `--note` | 相手と要点を20字程度で（例：「元請工事主任へ打設延期の説明」） | 空でよい |
   | 人数 | 「3人で2時間」は `--minutes` を人数分の合計（360）にし、`--note` に「3名×120分」と書く | 1人とみなして確認 |

   複数の対応が含まれていれば、イベントを分けて記録する（例：「2時間待って、そのあと棚入れ40分」→ `荷待ち` 120分 と `附帯作業` 40分）。

   ```bash
   python3 -m troublelog event <trouble_id> --action 連絡 --minutes 20 --at 2026-09-15T22:40:00+09:00 --actor "山田" --note "元請工事主任へ打設延期の説明"
   ```

3. **フィードバック**：出力の `time_band` が `時間外` / `深夜` / `休日` なら、責めずに事実として一言添える。
   「記録しました（深夜帯・20分）。この件の対応は累計 {total_minutes} 分です。」

## B. ステータスを更新する

「解決した」「片付いた」→ `解決`、「まだ続いてる」→ `対応中`。

```bash
python3 -m troublelog status <trouble_id> --set 解決
```

解決時は、そのトラブルの対応合計と時間帯内訳を `show` で確認して一言で伝える。

## C. 集計して報告する

「今月どれくらい？」「まとめて」と言われたら月を特定して集計する（指定がなければ今月）。

```bash
python3 -m troublelog summary --month 2026-09 --industry <業種ID>
```

`--industry` を省略すると全業種合算（`by_industry` / `minutes_by_industry` に内訳）。複数業種のログがある場合は業種別に分けて報告する。

出力を次の形式のMarkdownで報告する（数字は分→「X時間Y分」に変換）。

```
## {YYYY年M月} トラブル対応サマリ

- トラブル件数：N件（解決 a／対応中 b／受付 c）
- 対応時間合計：X時間Y分
- **うち所定時間外：X時間Y分（全体のZ%）** ← 深夜 / 休日 の内訳も併記

| 時間帯 | 時間 |
|---|---|
| 所定内 | |
| 時間外 | |
| 深夜 | |
| 休日 | |

| 分類 | 件数 | 対応時間 |
|---|---|---|

| 対応内容 | 時間 |
|---|---|
```

最後に、事実に基づく気づきを最大2つだけ書く（例：「書類作成の7割が休日に発生しています」「設計変更・図面不整合は件数は少ないが1件あたりの対応時間が最長です」「荷待ちが月12時間、うち8時間が同じセンターです」）。
評価・説教・労務上の断定（「違法です」等）はしない。

## 注意

- 所定時間は業種パックの `work_hours`（既定 8:00〜17:00）。現場の実態と違う場合は環境変数 `TROUBLELOG_WORK_START` / `TROUBLELOG_WORK_END` で変更できると案内する（運送のように勤務時間が便ごとに違う場合は特に）。
- 時間帯はイベント開始時刻で判定している（22時をまたぐ対応は開始時刻側に計上）。精度が必要なら「21:30〜22:00」と「22:00〜22:30」に分けて記録する。
- ログは取引先との交渉に関わる情報を含む。集計結果を誰に見せるかは本人が決める前提で扱う。
